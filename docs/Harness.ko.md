### Cursor 구현 요청 · 경기 HUD와 입력 회귀

1. TypingLayout과 TypingScreen에서 남는 세로 공간을 경기장에 돌려준다. 문제·뜻·입력의 가독성과 키 터치 영역을 유지한다. 실제 발판에 적용된 PadLook을 관찰할 수 있도록 참가자 카메라 구도도 점검한다. 연습·관전자·로비에는 대결 카메라를 적용하지 않는다.
2. TypingPad의 PC TextBox 포커스 경로, 터치 가능 기기의 물리 키 바인딩, 화면 키 Activated 경로를 추적한다. Studio 진단에서는 O 키 수신, 포커스 소유자, 버퍼 반영 횟수와 카메라 변화를 대조해 누락 지점을 찾는다. 특히 포커스 해제 뒤 지연 실행된 재획득이 메뉴·채팅·다음 화면을 침범하는지 확인한다.
3. 대결·연습 중 활성 입력 소유자는 하나다. 물리 키와 화면 키는 같은 편집·제출 규칙을 사용하고, 같은 키 이벤트는 한 경로에서만 소비한다. TouchEnabled와 최근 입력 종류는 키보드 표시를 조절할 수 있으나 입력 자격을 결정하지 않는다. 창 활성·모달·채팅·문제 전환·대결 종료 시 소유권을 명시적으로 넘기고 단축키 바인딩을 정리한다.
4. 자동 하네스에서 입력 소유권 전이, 기기 전환 시 초안 유지, 자동 정답과 Enter의 중복 제출 방지, 최소 해상도 레이아웃을 검증한다. 데이터·점수·보상 규칙은 기존 검증을 함께 실행한다.
5. Studio 수동 검수는 PC, 568×320 가로폰, 1024×768 태블릿에서 한다. 두 참가자에게 구별되는 외형을 장착시키고 서로 먼 발판으로 배정한다. 기본 경기 화면에서 키보드와 뜻을 켠 채 내 발판 테두리와 상대 발판 외형을 각각 식별하고 양쪽 시점 스크린샷을 남긴다. 경기 종료 후 로비 카메라 복원도 확인한다.
6. 정식 경기와 연습에서 영문 전체, 특히 O·I·WASD, 반복 O, Space·Backspace·Enter를 입력한다. 예시로 `look out`을 입력해 버퍼가 정확히 일치하고 카메라 줌·이동·점프가 없는지 본다. 순위 패널 조작 직후, 채팅·메뉴·창 전환 후 복귀, 문제 전환 직후 첫 키도 반복한다. 채팅 중 입력은 채팅에만 들어가야 한다.
7. 실제 iOS/iPadOS 및 Android에서 터치 → 블루투스 키보드 연결·입력 → 연결 해제 → 터치 복귀를 검사한다. 첫 O 유실·이중 입력·원치 않는 OS 키보드 호출 없이 초안이 이어져야 한다. 자동 검사, Studio 에뮬레이터, 실기기 결과를 따로 보고하며 미보유 기기는 미검증으로 기록한다.

### 반복 결함 O 키 · 변경 시 회귀 검수

대결 또는 연습의 입력 처리, IME, 포커스, HUD 전환, 카메라 단축키, 터치·물리 키보드 전환을 수정할 때마다 아래 사례를 함께 검증한다. 판정 단위는 키를 한 번 눌렀다 떼는 동작이다. 한 번의 누름이 여러 이벤트 경로로 전달되어도 글자는 하나이고, 서로 다른 두 번의 누름은 간격이 짧아도 두 글자다.

| 재현 | 기대 결과 |
|---|---|
| 영어 대결 및 연습 진입 직후 첫 키로 O를 누른 뒤, 떼고 다시 O를 누른다. 빠르게, 그리고 간격을 두고 반복한다. | 버퍼가 순서대로 `o`, `oo`가 되고 카메라 줌은 움직이지 않는다. |
| 영어 대결에서 `balloon`을 입력한다. `l`을 눌렀다 떼고 바로 다시 `l`을 누른다. | 버퍼가 `ball`까지 이어지고 두 번째 `l`이 빠지지 않는다. `oo`도 같다. |
| `look out`을 입력하고 다음 문제에도 첫 키로 O를 누른다. | 자동 제출 직전 버퍼에 세 개의 o가 원래 위치에 있고, 새 문제의 첫 글자는 `o` 하나다. |
| 순위 패널을 여닫고, 채팅·Roblox 메뉴·창 전환에서 복귀하고, 한국어 연습에서 영어 연습으로 전환한다. 각 복귀 직후 O를 누른다. | 채팅 중에는 게임 초안이 유지된다. 영어 타자 화면이 입력을 다시 소유한 첫 키부터 반영된다. |
| 모바일에서 화면 O → 블루투스 키보드 O → 연결 해제 후 화면 O를 입력한다. | 동일 문제의 초안이 `o` → `oo` → `ooo`로 이어진다. |

**Cursor 자동 검사 요구사항.** 실제 입력 코드가 사용하는 중복 판정·소유권 로직에 같은 누름의 CAS/UIS 콜백을 양쪽 순서로 전달하고, 한 경로만 수신하는 경우도 검사한다. 이어서 O의 누름→해제→새 누름을 20ms 이내로 모의해도 두 번째 글자가 살아야 한다. 고정 시간 내 같은 KeyCode라는 이유만으로 별개 입력을 버리는 회귀를 잡는다. 이 동작 검사를 기존 검증 명령에 연결한다.

**실패 기록과 완료 판정.** 누락 또는 중복이 한 번이라도 발생하면 기기·입력 방식·화면 전환 순서, O 이벤트를 받은 경로, 당시 포커스 소유자, 처리 또는 무시 사유, 버퍼 길이 변화와 카메라 반응을 기록한다. 이 기록으로 실패한 전이를 회귀 사례에 추가하고 같은 절차로 재검사한다. 자동 검사, Studio PC, 모바일 블루투스 실기기의 관찰 결과를 각각 보고한다. 실행하지 않은 환경은 미검증으로 남긴다.

### M7 PC 한국어 타자

PC 설정의 타자 언어는 LanguageDataSheet의 PcTypingEnabled가 1인 행을 NativeName으로 보여 준다. 적용할 때 그 코드를 프로필 typing에 저장한다. 값이 없거나 지금은 PC 타자가 아니면 첫 PC 타자 언어로 시작한다. 모바일 세션은 MobileTypingEnabled만 사용하므로 저장값이 한국어도 그 접속은 영어다. PC로 돌아오면 저장값을 다시 쓴다. 메뉴 코드는 언어마다 분기하지 않는다.

서버는 정식 경기 참가 확정 때 플레이어별 세션 언어를 고정한다. 같은 문제 ID에서 영어 참가자는 en 열, 한국어 참가자는 ko 열을 쓰고, 등급·기본 점수·마지막 30초 ×2는 같다. 판정은 그 참가자에게 발급한 문제 ID·순번·언어다. 활성 문제의 해당 열이 비면 검증은 문제 ID와 열 이름을 알린다. 실시간 순위와 결산은 이번 경기에서 실제로 쓴 EN 또는 KO를 표시한다.

PC 한국어는 두벌식 키를 게임 안에서 조합한다. 운영체제 조합 글자는 Space 전까지 입력창 Text에 없으므로 그 창을 IME에 맡기지 않는다. 조합된 문자열이 정답과 같아지는 순간에 자동 진행한다. Enter는 현재 문제를 한 번만 채점한다. 영어는 기존 자동 정답과 Enter를 유지한다. 다음 문제의 입력칸은 빈 상태에서 시작한다. 모바일 터치와 모바일 블루투스 키보드는 영문 QWERTY다.

### 영어 뜻과 한국어 정답 진행 회귀 검수

- PC 설정에서 타자 한국어, 문제 뜻 English를 적용한 뒤 재접속한다. 경기와 연습에서 사과 / apple이 표시되고 사과로만 정답 처리된다. 끔과 한국어 기존 선택도 유지된다.
- 두벌식으로 별의 중간 입력 벼와 오답을 확인한 뒤 정답 자동 진행, 마지막 음절과 함께 누른 Enter 한 번, 연속 Enter, 다음 문제 첫 글자를 각각 검사한다. 경기 점수와 문제 순번 또는 연습 정답 수가 한 번만 오르고 다음 입력칸이 빈 상태인지 확인한다.
- 정식 경기와 연습에서 두벌식 키로 사과를 입력한다. 마지막 ㅏ에서 Space·Backspace·Enter 없이 즉시 한 번만 완료되어야 한다. 그 뒤에 오는 Space나 과가 다음 답안에 남지 않고, 다음 문제의 첫 키가 한 번만 보여야 한다. 영어 단어·공백 포함 문장을 회귀 검사한다. 일본어 추가 시 변환 후보 목록에만 정답이 있는 경우에는 대기하고, 입력란 전체에 정답이 반영되는 순간에는 추가 확정 키 없이 진행하는 사례를 실기기로 검수한다. 자동 검증과 실제 키보드 결과를 따로 기록한다.

### M5 개인 연습

개인 연습은 클라이언트 세션만 사용한다. 문제 원본은 QuestionDataSheet에서 이번 세션의 타자 언어 열이며 Kind가 Word 또는 Sentence인 행만 해당 모드에 들어간다. 영어는 대소문자, 공백, Backspace, 자동 정답, Enter를 쓴다. 한국어와 향후 추가 언어도 조합 중 글자를 포함한 전체 답안 일치 시 즉시 자동 처리하고 Enter도 동일한 완료 경로를 사용한다. 자동 정답 직후나 빈 입력의 Enter는 다음 문제를 완료하지 않는다.

검수: 원 안의 비참가자에게는 버튼 대신 원 밖 안내를 보여 기존 자동 참가를 유지한다. 원 밖 버튼은 다른 플레이어의 대결·결산 중에도 남는다. 연습을 열면 좌측 로비 HUD를 숨기고, 나가면 현재 서버 단계의 HUD를 되돌리며 입력 포커스를 해제한다. 시작과 종료로 캐릭터를 옮기지 않는다. 서버가 그 플레이어의 InMatch를 Play 또는 Result에서 확정하면 연습을 닫고 대결 또는 결산 화면만 남긴다. 연습 화면은 QuestionSubmit, 순위 갱신, RewardService, 프로필 저장을 호출하지 않는다. 568×320에서 문제, 현재 입력, 키보드 마지막 줄, 나가기가 함께 보여야 한다.

설정은 같은 로비 메뉴에서 연다. 열거나 닫아도 캐릭터 위치와 참가 대기 상태는 바뀌지 않는다. 다른 플레이어의 경기 중에는 설정이 유지되고, 자신이 참가자로 확정되면 언어 목록과 설정이 함께 닫히며 마지막 적용 값이 남는다. UI 언어 자동은 기존 Roblox 언어 감지를 유지한다. 선택 목록과 서버 검증은 LanguageDataSheet를 함께 읽는다. 뜻은 문제 ID와 선택한 언어 열로 읽고, 끄거나 빈 번역이면 영역을 접는다. 순위와 결산의 플레이 언어는 그 경기에서 각 참가자가 실제로 쓴 EN 또는 KO다. 타자 언어는 적용할 때 저장하고, 값이 없으면 영어다. 모바일 세션은 영어이며 저장한 PC 타자 언어는 유지된다. 프로필에 설정 필드가 없어도 기본값으로 연다. 비활성 코드는 UI 자동·뜻 끔으로 보이고, 잘못된 저장 요청은 기존 값을 유지한다. 저장 완료는 저장이 성공한 뒤에만 표시한다. 배경음악·효과음은 0~100의 5% 단위이며 기본 100%다. 슬라이더 이동은 SoundGroup 볼륨만 바꾸고 저장하지 않는다. 효과음은 손을 뗀 뒤 UIConfirm을 한 번 재생한다. X와 경기 시작은 미적용 음량을 마지막 적용값으로 되돌린다. 볼륨이 없는 프로필과 볼륨을 생략한 예전 저장 요청은 저장된 음량 또는 100%를 유지한다. 568×320에서는 본문을 스크롤해 슬라이더와 적용에 닿고 우상단 X는 고정이다.

언어 한 개를 추가할 때 수정할 데이터와 검수 항목:

- `tables/LanguageDataSheet.xlsx`에 행을 추가한다. Id는 소문자로 시작하는 2~8자이고 `auto`, `off`와 겹치지 않는다. NativeName은 그 언어의 자체 명칭이다. SortOrder는 0 이상의 정수다. UiEnabled, PcTypingEnabled, MobileTypingEnabled, GlossEnabled는 0 또는 1이다.
- 뜻을 켜면 `tables/QuestionDataSheet.xlsx`에 같은 Id의 열을 추가한다. 조회는 문제 ID와 그 열로 하고, 빈 칸은 뜻 영역을 접는다. PC 타자를 켜면 활성 문제의 그 열이 비어 있으면 안 된다.
- UI를 켜면 `src/localization/CoreStrings.csv`에 그 언어 열이 있어야 고정 문구가 번역된다. 언어 이름은 시트의 NativeName을 쓰고, 자동과 끔만 문자열 키를 쓴다.
- `python tools/sync_tables.py`로 `Table/LanguageDataSheet.txt`를 갱신한다. 선택 목록과 서버 저장 검증이 이 생성본을 읽는다.
- 검수: 언어 코드가 중복되거나 활성 플래그가 0/1이 아니면 실패한다. 활성 값만 목록에 나오고 서버에 저장된다. 기존 프로필의 비활성 코드는 화면에서 UI 자동·뜻 끔으로 보이고, 새 저장 요청의 잘못된 코드는 gold·exp·bestScore·grants와 기존 언어 값을 유지한다. PC와 568×320에서 같은 화면을 쓰고, 언어가 12개여도 목록 내부만 스크롤되며 마지막 언어와 뒤로 가기·적용·닫기에 도달한다. 순위와 결산은 이번 경기의 실제 타자 언어를 표시한다. PC 타자가 켜진 언어의 활성 문제 칸이 비면 문제 ID와 열 이름으로 실패한다. 테스트용 언어는 배포 시트에서 활성화하지 않는다. 배포 활성 집합을 바꾸면 `tools/verify.py`의 기대 집합도 함께 수정한다.

튜토리얼은 프로필과 UI 언어를 읽은 뒤에만 자동으로 연다. 로딩 중에는 안내를 그리지 않는다. 프로필 열기 실패는 미확인으로 취급하지 않는다. 단계 원본은 TutorialDataSheet이고 문구는 CoreStrings.csv다. Enabled가 1인 행만 순서대로 보여 주며 단계 표시의 분모도 그 개수다. 발판 꾸미기 행은 Enabled 1이고 활성 단계는 1/4~4/4다. 2배 문구의 시간과 배율은 IngameConstants.Match.DoubleScoreSeconds와 EndScoreMultiplier를 읽는다. 완료와 건너뛰기는 tutorialSeen을 true로 저장하고 같은 요청을 다시 해도 결과는 같다. 경기 참가로 닫히면 저장하지 않고, 그 접속의 결산 뒤에 자동으로 다시 열지 않는다. 설정의 다시 보기는 설정 임시값을 유지한 채 첫 페이지를 덮고, 닫으면 설정으로 돌아간다. 이미 완료한 플레이어도 다시 보기에서 발판 꾸미기 단계를 본다. 다른 플레이어의 경기 시작은 안내 페이지를 유지한다.

검수: 568×320에서 본문 스크롤과 이전·다음·건너뛰기가 겹치지 않고 마지막 페이지의 완료가 눌려야 한다. 첫 페이지는 카드 위로 노란 원이 보이도록 아래에 둔다. 활성 4페이지는 1/4~4/4다. 기존 프로필에 tutorialSeen이 없으면 미확인이다. 튜토리얼 저장은 gold·exp·bestScore·grants·uiLocale·gloss를 유지하고, 보상 저장과 언어 저장은 tutorialSeen을 유지한다. 중복 단계 ID와 0/1이 아닌 Enabled는 실패한다.

전체 랭크는 로비 버튼에서 SafeRoot 팝업으로 연다. 서버가 OrderedDataStore에서 상위 50명을 조회하고, 인원수와 60초 캐시는 IngameConstants.Rank에 둔다. 같은 서버에서 캐시가 유효하면 다시 조회하지 않고, 동시에 들어온 조회는 한 번의 요청으로 합친다. 성공한 빈 목록은 실패가 아니다. 이전 목록이 있는 갱신 실패는 이전 목록과 갱신 지연 안내를 함께 남긴다. 개인 최고 점수는 프로필 저장이 성공한 뒤에만 반영한다. 저장값은 기존값과 새 값 중 큰 값이며 더 낮거나 같은 값은 기록을 내리지 않는다. 랭크 반영이 실패해도 완료된 보상 정산은 다시 실행하지 않는다. 실패한 기록은 같은 접속에서 제한된 횟수만 다시 쓰고, 다음 프로필 로드에서 다시 반영한다. Studio scope와 live scope를 분리한다.

검수: 한 플레이어의 정식 점수 100, 80, 120은 최고 점수와 전체 랭크가 100, 100, 120이 되고 이후 연습 150은 120을 유지한다. 120, 120, 100은 1위, 1위, 3위다. 상위 50명 밖에서도 최근 집계된 내 순위는 공동 10,000위까지 표시한다. bestScore가 0보다 큰 기존 프로필은 재접속만으로 순위에 오른다. ranked 없이 bestScore가 0인 기존 데이터는 미플레이로 두고 순위에 올리지 않는다. 이 변경 이후 0점으로 완료한 경기는 기록이다. 조회 실패 뒤에 캐시가 지나거나 다시 열면 복구할 수 있다. 정산 재시도는 보상을 중복 지급하지 않는다. 서로 다른 서버의 기록은 캐시 갱신 후 같은 목록에 나온다. 568×320·태블릿·PC에서 목록만 스크롤되고 닫기와 경기 시작 전환이 된다.

골드 상점은 로비 버튼에서 SafeRoot 화면으로 연다. 상품 원본은 ShopDataSheet다. 기본 외형 3종은 Release Default이고 가격 0이며 모든 프로필이 소유한다. 파일럿 샘플은 Release Studio이고 본체 20골드, 테두리 30골드, 이펙트 40골드다. 한 경기 완료 보상 50골드면 본체를 살 수 있다. Studio가 아니면 Studio 행은 목록과 구매에서 빠진다. Live 행이 있어야 운영 판매가 열린다. 클라이언트는 상품 ID와 buy 또는 equip만 보낸다. 서버가 판매 여부, 통화, 가격, 잔액, 소유를 확인하고, 골드 차감과 소유권 추가를 같은 SetCache로 처리한다. 이미 소유한 상품과 골드 부족은 잔액을 바꾸지 않는다. 장착은 소유한 부위 하나만 바꾼다. 미리보기와 닫기는 서버에 장착을 보내지 않는다. 저장된 조합은 쌓이는 StackPad의 본체·테두리·이펙트에 칠하고 Arena.Pads.PadN은 바꾸지 않는다. 이탈·휴식 복귀·다음 배정 전에 쌓인 발판을 지운다. 발판 본체 크기와 CanCollide는 유지하고 장식은 CanCollide를 끈다.

Achievement Rim은 골드로 살 수 없고, 잠겨 있으면 필요 점수를 보여 준다. 소유한 뒤에는 일반 Rim처럼 장착한다. starter_rim과 starter_effect만 테두리·파티클을 만들지 않는다. 정식 완주 199점은 타이틀 0개, 200점은 1개, 720점은 3개, 1,500점은 10개다. 같은 정산 재시도와 중도 퇴장·연습은 다시 지급하지 않는다. 자동이면 최고 ID를 장착하고, 수동 선택은 더 높은 점수를 받아도 유지된다. 결과창은 이번 정산의 새 타이틀과 Rim 이름만 스크롤로 보여 주고 닫기와 다음 경기 타이머를 가리지 않는다. EquippedTitleId는 로비와 경기 워프, 플레이, 결과에서 HumanoidRootPart 중심에 두고, 이름 하단을 머리 기본 자세에서 2스터드 위에 표시한다. 타이틀 글자는 닉네임 위에 가운데 정렬하고, 그 앞에 AchievementDataSheet.itemId 아이콘을 둔다. 단계가 바뀌어도 지우지 않는다. Idle·고개 흔들림·제자리 애니메이션은 따라가지 않고, 점프하면 몸 중심과 함께 오르내린다. 없으면 기본 이름을 유지한다.
금빛 숫자 미리보기와 경기 발판은 같은 프리셋의 순서·색·초당 10개·수명 0.85초를 쓴다. 최상단만 방출하고 경기 종료 후 숫자가 남지 않는다. 구매 전 닫기는 장착을 바꾸지 않는다.
검수: 구매 전 선택과 닫기는 골드·소유·장착을 유지한다. 구매 연타와 저장 실패 후 재요청은 한 번만 차감된다. 골드가 부족하면 잔액과 소유가 그대로다. 구매 후 장착하고 재접속하면 잔액·소유·장착이 같다. 2인 경기에서 외형이 다르고, 다음 경기에서 발판 주인이 바뀌면 이전 이펙트가 남지 않는다. 568×320, 1024×768, PC에서 세 탭·목록·미리보기·구매/장착·닫기를 쓸 수 있다. 보상·설정·튜토리얼 저장은 owned·body·rim·effect를 유지한다.

## 파일럿 문제집 검수

개인 연습은 QuestionDataSheet의 활성 행에서 단어·문장만 고르고, 마지막 다음은 첫 문제다. 정식 경기는 그 중 Enabled=1, RankEligible=1이며 참가 타자 언어의 정답이 모두 있는 행만 쓴다. 시작 시각으로 시드를 한 번 만들고 Essential·Daily·Growth·Proverb를 각각 섞는다. 단어 4개 다음 문장 1개이고, 문장은 일상·명언·일상·속담을 순환한다. 시작 칸은 경기마다 한 번 추첨한다. 20문제마다 단어 16개·일상 2개·명언 1개·속담 1개다. 모든 참가자의 N번째 문제 ID는 같고, 각자는 자기 언어로 맞히면 다음 문제로 간다. 같은 순번을 다시 요청하면 같은 ID와 배점을 돌려준다.

자동 검사는 문제 개수를 세지 않는다. 중복 ID, 활성 타자 언어 열의 빈칸, 등급표에 없는 GradeId, 소문자 a~z와 한 칸 공백이 아닌 영문, 앞뒤 공백과 연속 공백을 실패로 본다. 문제를 더 넣어도 이 검사를 고치지 않는다. ID 1~3과 book/책, moon/달, chicken/닭은 회귀로 남긴다. book은 두 번째 o가 들어와야 완료되고, 닭은 달에서 기다렸다가 마지막 받침이 들어온 순간에 한 번만 완료된다.

Studio에서는 2인 경기로 한 명은 EN, 한 명은 KO를 같은 문제 ID에서 맞혀 점수와 다음 문제가 각자 진행되는지 본다. 568×320 가로에서는 가장 긴 영문 `chickens eat rice`와 가장 긴 한국어 `물고기는 물을 좋아해`, 그리고 그 상대 언어 뜻이 키보드·입력란과 겹치거나 잘리는지 본다. 실행하지 않은 화면은 미확인으로 남긴다.

Excel은 첫 시트의 첫 행에 고유한 열명을 사용한다. 중복 키, 깨진 참조, 출력과 원본의 불일치는 작업 실패다. 숫자·플래그는 TXT에서 문자열이므로 소비 모듈이 초기화 때 한 번 파싱하고 ID 인덱스를 만든다. Enabled는 "1"을 명시 비교한다. 문항 점수·골드·경험치·레벨·상품 행은 **개발 샘플**이다. 활성 영어 열은 소문자 a~z와 단어 사이 한 칸의 공백만 허용한다. 활성 언어 열의 앞뒤 공백과 연속 공백은 실패다. PC 타자가 켜진 다른 언어 열은 활성 문제에서 비어 있으면 안 된다.

```powershell
python tools/sync_tables.py
python tools/build_item_icons.py
python tools/verify.py
```

첫 명령은 tables → src/ReplicatedStorage/Shared/Table로 직렬화한다. 두 번째는 아이콘 원본과 ItemDataSheet로 assets/item-icons/atlas와 ItemIconSlots.luau를 갱신한다. 데이터만 바꾼 경우 첫 번째와 세 번째로 충분하다. verify는 임시 경로에서 다시 생성해 누락·오래된 테이블, 아틀라스 페이지 픽셀과 슬롯을 비교하고 Rojo 빌드 내부의 주요 인스턴스를 확인한다. 새 표는 동일하게 직렬화되며 새 도메인의 고유 제약을 verify.py에 추가한다.

## 런타임 데이터 흐름

1. 서버가 경기 ID, 종료 시각, 참가자와 언어 스냅샷을 만든다. 클라이언트는 종료 시각에서 표시용 시간을 계산한다.
2. 서버가 문제 ID와 사용자별 순번을 발급한다. 클라이언트는 입력 버퍼를 로컬에서 갱신하고 완료 시 경기 ID·발급 순번·입력 문자열을 제출한다.
3. 서버가 세션·순번·기한·정답을 확인하고 해당 순번을 한 번만 소비한다. 서버가 선택한 Excel 행으로 점수와 골드를 계산한다. 확정 순위와 다음 문제를 UI에 전달한다. 중복 완료는 기존 상태를 재전달한다.
4. 결산은 참가자별 고정 결과를 만든다. 계정별 경기 ID를 보상 변경과 함께 기록해 재시도에도 한 번만 반영한다. 문제마다 DataStore를 쓰지 않는다. 순위 집계 실패는 이미 확정한 보상에 영향을 주지 않는다.
5. 플레이어 데이터 작업은 PlayerStore.getDocument(userId) → Open 성공 확인 → 캐시 변경 → 저장·Close 순서로 구성한다. 세션 잠금과 BindToClose를 유지한다. Studio와 live scope를 분리한다. 실패 중 구매·보상을 확정 표시하지 않는다. 상품 소유권, 재화 차감, 중복 처리 키는 같은 프로필 변경에서 확정한다.
6. 분석에는 경기·문제 ID, 언어, 입력 방식, 출제→정답 승인 시간, 결과를 사용한다. 원문 입력과 개별 키는 지표에 넣지 않는다. 개인 연습은 정식 경기 지표에서 뺀다.

## 정식 경기 플레이테스트 지표

서버가 문제를 처음 발급할 때 시각을 남기고, 같은 순번을 처음 승인할 때 출제→정답 승인 시간을 계산한다. 재조회는 그 시각을 유지한다. 같은 문제 ID·Revision·입력 방식 안에서 언어별 완료시간과 발급·완료 수를 비교한다. 경기 기록에는 시드, 데이터 버전, 참가 언어를 남긴다. 같은 정답을 다시 보내도 완료 수는 1이다. 종료나 이탈 때 열려 있던 문제는 미완료이고 평균 완료 시간의 표본에 넣지 않는다.

입력 방식은 물리 키보드, 화면 키보드, 혼용, 미확인이다. 화면 키만 쓰면 화면 키보드, 기기 키보드나 블루투스 키보드만 쓰면 물리 키보드, 한 문제에서 둘 다 쓰면 혼용이다. 승인 전에 끝난 문제는 미확인이다.

분당 점수의 분모는 참가 시간(초) / 60이다. 완주자는 경기 종료 시각 − 시작 시각, 중도 이탈자는 이탈 시각 − 시작 시각이다. 시간이 0이면 분당 점수는 없음이다. 마지막 30초 순위는 그 구간에 들어온 첫 관찰의 기존 정렬이다. 최종 순위와 점수는 결산에 쓰는 같은 정렬이다. 이탈자는 최종 순위가 없다.

Studio 서버 Output에는 경기 종료 때 요약을 한 번 출력한다. 문제 행은 문제 ID, 언어, 단어/문장, 입력 방식, 출제 수, 완료 수, 미완료 수, 평균 출제→정답 승인 시간, 표본 수다. 참가자 행은 언어, 완주 또는 이탈, 단어 수, 문장 수, 점수, 분당 점수, 마지막 30초 순위, 최종 순위다. 출력 후 집계를 비우고 다음 경기는 새로 시작한다.

재현: Studio에서 2인 경기를 연다. 한 명은 EN, 한 명은 KO로 같은 문제 ID를 맞힌다. 서버 Output의 언어별 완료 시간이 나뉘고, 완주자의 점수와 최종 순위가 결산 화면과 같은지 본다. 한 문제를 끝내지 않은 채 경기가 끝나면 그 행의 완료 수는 늘지 않고 평균 표본에도 들어가지 않는지 본다. 자동 검사와 Studio 출력을 따로 적는다. 실행하지 않은 2인 경기는 미확인이다.

## 12인 경기 통합 회귀

`python tools/verify.py`가 `tools/m2_check.luau`를 실행하고, 그 안에서 12인 시나리오를 두 번 돌린다. 같은 입력과 시각이면 두 번의 결과 문자열이 같아야 한다. Studio 서버 명령막대에서 Core 스모크를 실행해도 같은 시나리오가 돈다.

시나리오는 경기 서버가 쓰는 함수만 호출한다. 참가자 선발과 발판 배정은 MatchRules, 출제·점수·순위는 QuestionRules, 결산 금액은 RewardRules, 랭크 반영 여부와 동점 순위는 RankRules, 지표 요약은 PlaytestMetrics다. 가상 참가자의 프로필과 랭크 보드는 이 검사의 메모리에만 있고 DataStore에 쓰지 않는다.

기대 결과:

- 원 안의 12명이 서로 다른 발판을 받고, 13번째 대기자와 원 밖 플레이어는 빠진다. EN과 KO는 각자 언어의 문제를 받는다.
- 남은 시간 31초에 발급한 문제를 29초에 맞히면 기본 배율이고, 그 직후 발급한 문제는 ×2다. 같은 정답을 다시 보내도 점수, 완료 수, 보상은 한 번이다.
- 결과 행의 점수·순위와 지표 요약이 사용자별로 같다. 같은 점수는 먼저 도달한 사람이 앞이고, 도달 시각까지 같으면 작은 UserId가 앞이다. 전체 랭크의 동점은 공동 순위이며 다음 순위를 건너뛴다.
- 0점 완주는 결과표에 남고 골드·경험치는 0이며 랭크 기록은 0점이다. 중도 이탈자는 승인된 정답 골드만 받고 완료 보상·경험치·최종 순위·랭크 기록이 없다. 경기 나가기는 MatchLeave로 현재 matchId만 보낸다. 서버는 Play와 본인 배정이 맞을 때만 그 플레이어를 placeInLobby로 옮기고, 보상 저장 뒤에 forget한다. ProfileService.close는 접속 종료에서만 호출한다.
- 다음 경기는 참가자 구성이 바뀌고, 점수·발판·문제 순번·×2 순위·지표가 새로 시작한다. 첫 경기의 늦은 제출은 두 번째 경기 점수를 바꾸지 못한다. 더 낮은 두 번째 점수는 저장된 최고 점수와 테스트 보드를 내리지 않는다.
- 대결 시작 시 비참가자 중 경기장 안에 있는 사람은 로비로 옮기고 Arena.Wall.InWall.CanCollide를 켠다. 대결이 끝나면 CanCollide를 끈다. 참가자는 발판에 남는다.
- 발판 1단 연출이 시작될 때 본인 클라이언트만 PadLevelUp을 한 번 재생한다. 새 발판이 보이기 전에 캐릭터를 가진 클라이언트가 Y에 1 stud을 한 번에 더한다. 서버가 그 이동을 보간하지 않는다. 발판 윗면은 발 아래에 두고, 그 Y는 0.2초 동안 유지한다. 카메라는 그 Y를 같은 프레임에 따른다. 발판 크기와 다음 단은 0.2초다. 25점이면 0.2초 간격으로 5회, 약 1초다. AssetId가 비어 있어도 연출은 진행한다. 대결 카메라는 HumanoidRootPart 높이를 같은 프레임에 따라가며, 거리와 각도는 유지한다. 나가거나 휴식이 되면 카메라 바인딩은 하나뿐이고 이전 방식으로 돌아간다. 결산 30초 동안은 쌓인 발판을 유지하고 카메라 회전으로 주변을 볼 수 있다.
- 누적 점수 5점마다 발판 1단이다. 0→4는 0단, 4→5와 5→10은 1단, 0→25와 3→28은 5단, 28→30은 1단이다. 5단은 1초이고 10단은 10 studs다. 서버가 단수와 캐릭터 높이를 확정하고, 클라이언트는 BasePad 복제본의 크기와 테두리 회전만 그린다. 결산이 끝나기 전에는 쌓인 발판을 치우지 않는다. 나가기는 그 연출을 멈춘다.

실제 클라이언트에서만 볼 항목:

- Studio에서 클라이언트 2개를 열고, 한 명은 EN, 한 명은 KO로 같은 경기를 끝낸다. 양쪽 결산 화면의 순위와 점수가 같아야 한다.
- 결산 목록 12행을 PC와 568×320 가로에서 연다. 목록만 스크롤해 1위부터 12위까지 가고, 본인 행은 다른 색으로 구분한다. 자동 검사는 568×320 결산 목록의 12번째 행이 스크롤 영역에 들어가는지만 계산한다.
- 인게임 순위 서랍은 568×320에서 상위 5명과 본인 행만 그린다. 서랍이나 전체 랭크 창을 닫은 직후 첫 O가 정답 칸에 들어가는지는 기기에서 본다.

## 반응형 UI 검수

StarterGui는 LandscapeSensor이고 클라이언트는 CoreUISafeInsets가 적용된 SafeRoot의 AbsoluteSize를 측정한다. 크기가 바뀌면 Compact, ContentWidth, TouchTarget 속성을 다시 계산한다. 공통 화면은 속성 변경을 구독하고 목록·미리보기·키보드 영역을 재배치한다. 터치 키보드 노출은 입력 방식, 화면 밀도는 사용 가능 크기로 결정한다. 터치가 가능한 노트북과 외장 키보드 태블릿도 별도 확인한다.

| Studio 에뮬레이션 기준 | 점검할 압박 조건 | 통과 기준 |
|---|---|---|
| 568×320 가로 | 짧은 세로, 모바일 키보드 4행, 긴 문제 | 문제·입력·Enter 동시 노출. 키 행이나 순위 패널이 겹치지 않음 |
| 844×390 가로 | 노치·상단 Core UI, 긴 번역 | 양쪽 회전에서 닫기·Backspace가 안전 영역 안에 있고 마지막 글자 보임 |
| 1024×768 태블릿 | 상대적으로 좁은 가로 비율 | 상점 목록/미리보기/버튼 접근 가능. 긴 목록은 내부 스크롤 |
| 1366×768 PC | 물리 키보드·창 크기 변경 | 터치 키보드 없이 문제 공간 확장. 열린 화면·입력·선택 보존 |

이 해상도와 36/44 UI 픽셀 터치 목표는 **초기 검수 기준**이다. 출시 최소 사양은 실기기에서 정한다. 작은 화면에서는 순위 행 수와 장식을 먼저 줄이고, 긴 설명은 줄바꿈·스크롤한다. 핵심 점수·언어·입력 키를 잘라내지 않는다. 화면 작업의 증빙에는 해상도, SafeRoot 크기, 입력 방식, 언어, 해당 화면 스크린샷과 관찰 결과를 기록한다.

- UI 패널 2종과 중립 발광·반짝임·버스트 원본, 해당 아틀라스 4장, 기존 이미지 ID 및 영역 좌표를 함께 복사했다. Shared.UIImageUtil.apply(panel, "panel-9slice")로 사용한다. Studio 프리뷰는 이 경로로 9-slice를 실제 호출한다. 대상 경험에서 이미지가 로드되는지 확인하고, 권한이 다르면 복사한 페이지를 게시해 UIImageAssetIds를 갱신한다.
- 화면 얼굴은 UiChrome이 고른다. 흰 패널은 panel-9slice와 남색(#172945) 글자, 선택은 selected-9slice와 흰 글자, 주요 행동은 primary-9slice와 남색 글자, 터치 키는 keycap-9slice다. 숫자 아이콘은 ItemIconUtil, 이름 이미지는 UIImageUtil만 쓴다. 로비의 개인 연습은 Practice, 상점은 Shop, 랭크는 아이템 10073이다. 세 버튼은 글자 없이 우측 경기 상태 카드 바로 위 한 줄이고, 아이콘은 정중앙이며 한 변의 약 60%다. 연습이 가능하면 primary 노란 배경이고, 대기 구역에서는 같은 아이콘의 흰 배경으로 입력을 막는다. 설정은 아이템 10063을 상단 검은 원에 둔 버튼이고 ScreenInsets는 TopbarSafeInsets이다. 골드 표시는 아이템 1이다. 상점 그림은 ShopDataSheet의 상품 ID를 UI 키로 쓴다.
- Studio Play에서 F7로 치트 창을 열고 닫는다. 모든 데이터 초기화는 골드·경험치·최고 점수·소유·장착·타이틀·설정을 기본값으로 되돌리고, 골드 변경은 파라미터1만 반영한다. 게시된 서버에는 CheatRequest가 없다. 리스폰과 창 크기 변경 후 SafeRoot가 하나인지 확인한다. PreviewCoreUI에서 패널 모서리·문자열·Output을 확인한다. 실제 저장 왕복은 M4 테스트 계정으로 수행한다. 게시할 Lobby Place의 최대 플레이어 수를 12로 설정하고 게시된 값도 확인한다. Luau의 경기 정원과 별개인 Place 설정이다.

### 글로벌 랭킹 운영 검증

로비 전광판의 본문 글자 높이는 같은 행 얼굴 높이의 65%이고, 기록이 3개여도 10개일 때와 같은 크기다. 순위와 점수는 Bold, 닉네임과 나머지 값은 Medium이다. 얼굴 열 제목은 비우고 그 너비는 닉네임과 숫자 열에 둔다. 해상도를 올려도 글자 픽셀을 같은 비율로 키워 같은 거리에서 더 작아지지 않는다.
로비 전광판 Workspace.Rank.Rank.SurfaceGui와 랭크 창은 같은 Top 50 스냅샷의 앞 10명을 대조한다. 순위·닉네임·점수·분당타수·언어가 같고, 순위가 바뀐 뒤에도 얼굴과 닉네임은 같은 userId를 가리킨다. 등록자가 10명 미만이면 있는 행만 보이고, 모바일 가로에서도 10위까지 스크롤 없이 읽힌다. 전광판 오브젝트가 없어도 랭크 창은 열린다.
Studio와 라이브는 별도 scope와 MemoryStore 이름을 쓴다. 두 테스트 서버에서 각각 랭크를 열어 Top 50과 CPM·언어가 같은지 확인한다. 신기록 저장 직후 ‘집계 중’에서 다음 집계의 개인 순위로 바뀌는지, 마지막 컷 동점자는 공동 순위이고 미달자는 개인 점수만 오르는지 확인한다. 집계 실패 시 이전 완료본을 표시하는 경우와 최초 집계가 없는 경우를 구분한다.

로비 좌중단 패널은 프로필 로드, 완주 보상 지급, 골드 구매 후 값을 확인한다. 친구 0~4명 입퇴장, 같은 서버의 비친구, 모바일 조이스틱과의 간격 및 경험치 레벨 경계를 검수한다.
